# kz_variety_fix — Roblox PC KZ, V7.20

Обновление движения, воды и механик карты. Цель — поведение, близкое к открытому CKZ; точное совпадение с закрытым движком CS2 или настройками CYBERSHOKE не заявляется.

[Скачать ZIP](kz_variety_fix_updated.zip?raw=1) · [Открытие и откат](INSTALL_KZ_VARIETY_FIX.md) · [Что изменено на карте](SCENE_CHANGES_RU.md)

## Исправления V7.20

- **Основной мотор.** Проверка реальными float32-типами обнаружила 126 деталей, на которых старое построение формы завершалось `Degenerate brush` и включало запасной мотор. Формы Part/WedgePart/CornerWedgePart теперь строятся из известной локальной геометрии. Все 16064 примитивные коллизии карты проходят построение.
- **Surf.** Проекция скорости больше не обнуляется из-за погрешности float32. Сохраняется касательная составляющая; удар в стену и движение против склона не превращаются в искусственный разгон. Общая клиентская/серверная проверка земли по CKZ исключает ложный пол над крутой рампой возле стены.
- **Вода.** Исправлены прилипание ко дну, переход из плавания в мелкую воду и ошибочный наземный прыжок при всплытии. Восстановлена исходная глубина одной зоны, открыта другая перекрытая зона с сохранением сухого края. Автоматические траектории проверяют все 11 водных объёмов.
- **Расположение блоков.** В place добавлены 267 зон по исходным координатам: 9 Single, 8 Multi, 8 Anti-Bhop и 242 Teleport. Они связываются с оригинальными сущностями, сохраняя фильтры, I/O, направления и задержки. Дублирования игровых TP нет. В тренировке добавлены два Reset; пять Sequential-платформ остаются в своей тренировочной полосе.
- **Усилители и конвейеры.** Четыре `trigger_push` с `triggeronstarttouch=1` дают полный однократный импульс. Конвейер учитывается как скорость опоры: трение действует относительно ленты, при прыжке её движение наследуется один раз.
- **Лестницы.** Приседание меняет физический hull и скорость прямо на лестнице, включая принудительный duck/unduck. Сохранены боковое движение, отрыв и выход сверху.
- **Диагностика.** При fallback очищается маркер новой сборки; причина находится в `Player.KZBrushFallbackReason`, а backend обозначается как `KZClassicFallback`.

Стандартная камера и PC-управление сохранены, экранные кнопки не добавлены. HUD получает виртуальную скорость в CS units/s. V5, `KZBrush_V1` и резервные скрипты сохранены; изменения старых свойств карты перечислены в `scene/manifest.json`.

В Play у HumanoidRootPart основного мотора должен быть `KZMovementBuild=2026-10-20-r1`. Ожидаются `KZBrushCount=16064` и `KZBrushMeshQueryCount=20`.

## Проверки

[BUILD_REPORT.json](BUILD_REPORT.json) содержит версии, хеши, число сценариев и ограничения проверки. Используются:

- исполняемые тесты настоящих модулей, клиента и сервера под Luau;
- Lune 0.11.0 с float32 Vector3, полноценными CFrame и реальными объектами RBXL;
- проверка размещения зон, воды, конвейеров и траекторий на примитивной геометрии всей карты;
- независимое чтение всего RBXL через Rojo 7.7.1, компиляция всех 429 скриптов, проверка ZIP/CRC и отката;
- аудит сохранности всех исходных ID, родителей и свойств за пределами явно объявленных изменений.

Lune не запускает нативный движок Roblox. Коллизии 20 MeshPart, реальная репликация двух клиентов, визуальная сторона водного отверстия и ощущения движения требуют [проверки в Studio](PLAYTEST_RU.md). Мотор остаётся клиентским, сервер обрабатывает карту и проверяет телеметрию; Chickynoid не интегрирован.

## Разработка

Python 3.11+, зависимости `requirements.txt`, Luau и Rojo. Для геометрических проверок нужен Lune; его официальный архив проверяется по SHA-256.

```bash
python -m pip install -r requirements.txt
python -B tools/install_lune.py --target /tmp/kz-lune/lune
python -B run_luau_tests.py --luau /path/to/luau
python -B -m unittest discover -s tests -p 'test_*.py' -v
/tmp/kz-lune/lune run tools/float32_regressions.luau
/tmp/kz-lune/lune run tools/audit_scene.luau
/tmp/kz-lune/lune run tools/verify_scene.luau
/tmp/kz-lune/lune run tools/water_map_probe.luau
/tmp/kz-lune/lune run tools/conveyor_map_probe.luau
python -B build_place.py --luau-compile /path/to/luau-compile --rojo /path/to/rojo
python -B build_place.py --check --luau-compile /path/to/luau-compile --rojo /path/to/rojo
```

Исходники привязаны по ID в `src/manifest.json`. Изменения сцены заданы в `scene/`: отдельно добавляемые модели и точечные правки существующих свойств. Сборщик сохраняет остальные значения побайтово и отклоняет устаревшее размещение. `prepare_scene.py --lune /path/to/lune` регенерирует план сцены; при намеренном изменении уже размещённых объектов собирай с проверенной базой через `--base`, не обходи проверку несовпадений.
