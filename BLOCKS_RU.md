# KZBlockController / V7.18

Контроллер находится в `ReplicatedStorage/KZClassic/KZBlockController`. Он управляет правилами блоков отдельно от формы препятствий и физики персонажа. `KZBhop` оставлен как совместимый вход в тот же модуль. Сервер проверяет касания и телепорты; клиент получает общую anti-bhop-политику через `KZMapData`.

| `KZBlockType` | Поведение |
| --- | --- |
| `Normal` | Обычная поверхность; ускорение, трение и прыжок остаются у существующего мотора. Без атрибутов платформа также остаётся обычной. |
| `SingleBhop` | Один своевременный отскок. Возврат на последний использованный bhop-блок вызывает TP. |
| `MultiBhop` | Повторные отскоки разрешены; превышение времени стояния вызывает TP. |
| `SequentialBhop` | Запоминает все использованные sequential-блоки текущей цепочки; A → B → A вызывает TP. |
| `AntiBhop` | Прыжок разрешён после заданного времени на земле; значение `0` запрещает прыжок в зоне. |
| `Teleport` | TP после заданного времени контакта; можно выбрать именованное назначение или текущий CP. |
| `Reset` | Очищает single/sequential-состояние и часы контактов текущего игрока. |

Сохранено поведение открытого CKZ: для Single учитывается последний bhop-блок любого типа. Поэтому Single A → Multi B → Single A разрешён; для Sequential хранится вся использованная последовательность. Это разные механики. Отскок от обычной земли, подтверждённый захват лестницы, успешный TP, рестарт и новая попытка очищают цепочку. Само сохранение CP её не очищает. Игроки не разделяют состояние использованных блоков.

Для bhop срабатывает строгое `время стояния > задержка`; для Teleport — `время контакта >= задержка`. Контакт в воздухе не расходует bhop-попытку. Выход из зоны удаляет её часы контакта.

## Существующие исходные триггеры

Сохранены ID, Source-границы и свойства импортированных сущностей. В этом наборе есть 9 Single, 8 Multi, 12 Teleport типа 10 и 8 Anti-Bhop; Sequential типа 13 нет. В данных также есть 230 сущностей класса `trigger_teleport`: класс и номер типа Mapping API являются разными признаками, их счётчики нельзя просто складывать. Подробности специальных типов находятся в `special_blocks_audit.json`.

Это инвентаризация данных внутри проекта. Она не доказывает соответствие каждого блока текущей версии карты на CYBERSHOKE и не заменяет прохождение в Studio.

## Явная привязка Roblox-зоны

На `BasePart` внутри активной модели карты можно задать атрибуты в Studio. Регистрация происходит при запуске сервера и подготовке клиентского мотора; после изменения атрибутов перезапусти Play. Геометрия и свойства коллизий части при регистрации не меняются.

| Атрибут | Тип | Назначение |
| --- | --- | --- |
| `KZBlockType` | String | Одно из значений таблицы выше. `NormalBlock` также принимается как `Normal`. |
| `KZBlockId` | String | Уникальный непустой ID. Одинаковые ID отклоняются у обеих зон. |
| `KZSourceBoundsMin` | Vector3 | Минимальная граница триггера в Source-координатах и CS units. |
| `KZSourceBoundsMax` | Vector3 | Максимальная граница в той же системе координат. |
| `KZBlockDelay` | Number | Задержка: по умолчанию 0.1 s для bhop, 0 s для Teleport. |
| `KZDestination` | String | Имя существующего назначения из `KZMapData.byName`. |
| `KZReturnToCheckpoint` | Boolean | Использовать выбранный CP. Такой TP учитывается как практика и меняет категорию забега на TP. |
| `KZAntiBhopTime` | Number | Время Anti-Bhop, по умолчанию 0.2 s; `0` запрещает прыжок. |
| `KZResetSpeed` | Boolean | Сбрасывать скорость при TP; по умолчанию true. |
| `KZDisabled` | Boolean | Начальное отключение зоны; по умолчанию false. |

Source-границы задаются явно: размер части в studs и её поворот не подменяют границы триггера. Для `Normal` без границ отдельная зона не нужна. Для остальных типов нужны обе корректные границы. Для Single/Multi/Sequential/Teleport также нужно назначение или `KZReturnToCheckpoint=true`.

Если выбран возврат на CP, но CP нет, используется `KZDestination` как явно заданный запасной адрес. Если нет обоих адресов, TP не выполняется. При возврате на CP восстанавливаются приседание и взгляд.

Цвет, имя части, MeshPart и форма препятствия не выбирают механику. Longjump, Ladder, Surf Ramp, Crouch, Edge, Strafe и Drop описывают препятствия; эти названия не являются допустимыми `KZBlockType`. Например, наклонная поверхность продолжает обрабатываться существующими surf-коллизиями.

Ошибки неизвестного типа, отсутствующего ID, дублирующегося ID или неверных границ видны в Output с префиксом `[KZBlockController]`. Контроллер просматривает только активную модель карты; V5 и `KZBrush_V1` не регистрируются как игровые зоны.

## Проверка в Studio

Проверить один своевременный прыжок и возврат Single; серию Multi и остановку дольше задержки; Sequential A → B → A до/после Reset; Anti-Bhop со временем 0 и 0.2; Teleport с задержкой; возврат на CP и отсутствие CP. Повторить для двух игроков, после рестарта и TP. Эти реальные проверки ещё не выполнены в облачной среде.
